# 石走り編を最初の完成目標にする（制作方針・2026-09-24）

> 実装された専用フロー、実行方法、保存隔離および未検証事項は [Ishibashiri Demo Flow](IshibashiriDemoFlow.md) を参照する。

基準: main `c54ad09f62eaed3633c116f90effbb74389245ab`。これは**制作範囲と着手順の決定**であり、体験版の実装・完成・UE実機検証を示す文書ではない。

## 目標

「禍祓い」の最初に見せられる体験を、白面が石走りの痕跡を追い、巨猪へ取り付き、3つの禍根を祓って鎮める**石走り編**に絞る。想定する流れは `Title → 既存Prologue → IshibashiriApproach → Ishibashiri → 石走り編の短い結末`。既存の4戦Campaignは開発用の基盤として維持し、石走り編の結末を4戦全体のEndingとして扱わない。

体験時間の仮目標は初見で10〜20分。既存の接近路は資料上3〜5分の設計で、実測はまだない。初回の人間プレイで計測し、説明が長い場合はカードの枚数・移動距離・再挑戦待ち時間を調整する。新しいボスや広い島の探索を追加して尺を埋めない。

「大歳ノ島」は空気感・場面のまとまりの**品質参照**に留め、同じ島、民俗モチーフ、構図を再現する制作指示にはしない。独自の「観察 → 回避 → 登攀 → 鎮静」と、白面に禍が残る余韻を優先する。

## 既存の物語カードを使う最小構成

Prologueは現在の4枚をまず流用し、初見プレイで冗長な場合だけ**体験版側**の表示枚数を調整する。鎮静後は既存のInterlude1の冒頭2枚「石走りは生きている。息が戻る。」「水の底で、同じ脈動が続いている。」を石走り編の区切りとして再利用し、短い終了表示からタイトルへ戻す。「第二の主　淵纏い」は本編に残す。全編Endingの仮面着脱や禍津根鎮静を、この時点の結末として流さない。

専用起動動線を加える際は、本編Campaignの状態遷移とセーブを共有・上書きしない。まずセーブなしの体験版を想定し、再挑戦は石走り戦の既存Retryを使う。タイトルから結末までの実行が可能かはUE検証後に判定する。

## 最初の実行ゲート

1. `Tools/RunIshibashiriReviewGate.ps1 -DryRun` で予定されるコマンドを確認する。詳細な既存ゲートは `Docs/IshibashiriReviewGate.md`。
2. UE環境で `.\Tools\Prototype.ps1 -Action Build` を実行し、必要なら `-Action Test -Approach -TestFPS 60` / `30` と `-Action Test -Climbing -TestFPS 60` / `30` を同じビルドで確認する。既存のレビューゲート実行とログ収集を優先する。
3. 従来の単体石走り戦と4戦Campaignを混同せず、**新たな石走り編用の起動動線**が必要かを実機で判断する。必要なら既存Campaignの章進行を壊さない明示的な選択肢として実装し、対応する入力テストを加える。
4. 30/60の固定刻みテストは実GPUの性能測定ではない。実描画、カメラ、接触、音、入力と、使うPCのフレーム時間を別に記録する。
5. 最初の実機ゲートが通るまで、新しい3D素材を本番アセットと呼ばず、後半3戦の本番アートへ着手しない。

## 見せられる状態の判定

- 初見プレイヤーが、開発者による操作説明なしで接近路から石走りの鎮静後のカードへ到達できる。失敗とRetryを含めて原因を把握できる。
- 11地点の移動、前脚への取り付き、Cling、禍根の3/3、Calm、Retryが現行ビルドで破綻せず、勝利以外で主が死亡・消滅しない。
- 画面に見える地形と巨体が同じ画風でまとまり、通常プレイ時に制作途中のPrimitive、欠落テクスチャ、不要なDebugGuidanceが目立たない。
- 少なくとも接近路入口、境界石、石走り初見、突進、前脚Grab、登攀、禍根浄化、鎮静の実機キャプチャを確認する。目視で見劣りする場所を優先修正する。
- 予告と鎮静に実音があり、ゲームパッドとキーボードで遊べる。物理コントローラーの結果を模擬入力テストの結果で代用しない。
