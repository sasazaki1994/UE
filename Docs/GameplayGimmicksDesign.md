# 禍祓い — ゲームプレイギミック設計

Status: Adopted Design / implementation staged

本書は『禍祓い』の主戦を、単純な「登る → 禍根を斬る」の繰り返しにしないための共通ギミック方針を定義する。既存の `Grab / Climbing / Stamina / Kakon / Nushi Progress / Retry` を中心に再利用し、新規システムを必要最小限に抑える。

## 1. ゲームプレイの4本柱

### 1.1 境断ち — 禍を探し、道を見抜き、最後に祓う

境断ちは通常攻撃だけの武器にしない。最終的には次の3用途を持たせる。

1. **禍の探知**
   - 構え中、近い禍根・禍の流れに反応する。
   - 本番版では現在のデバッグ的な赤い禍根マーカーを常時表示せず、境断ちを構えた時の反応へ段階的に置き換える。
   - 方向は「正解地点を直接指す」のではなく、反応の強弱・刀身の発光・音で示し、観察の余地を残す。

2. **境の看破**
   - 一時的に、登攀可能な筋、禍で塞がれた部位、次に利用できる足場を読み取りやすくする。
   - 常時HUDナビゲーションの代替ではなく、迷った時の能動的な情報取得として使う。

3. **祓い斬り**
   - 発見・露出した禍根を最終的に切り離し、共通 `Kakon → Progress → State Calm → Encounter Completed` へ接続する。
   - 主そのものを殺傷するための決着手段にはしない。

### 1.2 主の習性と攻撃を利用する — 巨体そのものを攻略装置にする

主の攻撃は「避けるだけ」の障害物ではなく、地形や主自身の状態を変化させる攻略手段にする。

共通ルール:
- プレイヤーが攻撃を誘導する。
- 攻撃が特定の地形・部位へ当たると、新しいGrab機会・足場・登攀ルート・休息地点が生まれる。
- 弱点露出のためにHPを削るのではなく、主の行動を利用して禍根へ近づく。
- 既存のAIやBoss固有Action Stateの上に実装し、共通Grab/Stamina/Nushiを壊さない。

既存実装の基準:
- **淵纏い**: 噛みつきを指定岩へ誘導 → 回避 → Snagged → 頭へGrab。この構造を本方針の基準実装とする。
- **峰抱き**: 主自身の崖登りと姿勢変化を、身体上のルート変化として利用する。
- **石走り**: 将来、突進を岩壁・倒木・石柱へ誘導して登攀開始点や分岐を作る方向が適合する。

### 1.3 穢れた左腕 — 情報取得とRisk / Reward

左腕は境断ちとは別の能力として扱う。禍に近い存在だからこそ、通常では分からない情報を読むことができる。

想定機能:
- 禍の流れ、禍根の大まかな位置、危険な足場、主の次の大きな動きの兆候を短時間強調する。
- 長時間使用には代償を持たせる。

初期の代償候補:
- Stamina回復速度低下
- 画面・音の禍表現増加
- Cling時の余裕減少

実装時の制約:
- HPを削るような常時ペナルティにはしない。
- 初期実装では1つの代償だけ採用し、複雑な状態異常システムを新設しない。
- 境断ちの探知と役割が重複しすぎないよう、境断ちは「方向・対象」、左腕は「状態・危険・流れ」を読む役割に分ける。

### 1.4 Grab / Cling / Stamina — 巨体上での身体アクション

既存システムを本作の中核として維持する。

- Grab: 主・環境への接続
- Climbing: ルート移動
- Cling: 揺れ・姿勢変化に耐える能動操作
- Stamina: 行動時間の制約と休息地点選択

新ギミックはこの4要素へ接続し、別ゲームのような独立ミニゲームを増やさない。

## 2. 補助ギミック

### 2.1 札・注連縄による一時封印

主を倒すためではなく、身体の一部や禍の流れを短時間だけ抑えるために使う。

想定例:
- 揺れ頻度を一時的に下げる。
- 腕・尾・頭など特定部位のActionを短時間抑える。
- 禍根を覆う禍を数秒だけ薄くする。
- 新しい足場へ移るための安全時間を作る。

基本ループ:
`登攀 → 留め所へ到達 → 札を貼る → 行動変化 → 新ルート開通 → 禍根へ進む`

制約:
- 消耗品管理ゲームにはしない。戦闘中の所持数管理やクラフトは当面実装しない。
- 各主で1〜2回使う「攻略手順」の範囲に留める。
- 封印だけで禍根浄化やEncounter完了はできない。

### 2.2 身体変形ルート

主の姿勢・Action Phaseによって登攀ルートを変化させる。

- 立つ / 伏せる / 巻き付く / 崖へ腕を掛ける等でNodeやAnchorの位置・有効状態が変わる。
- 既存の親Transform追従を利用し、自由登攀システムの新設は前提にしない。
- 「どのPhaseでどこへ移るか」をプレイヤーが観察して判断できるよう予告を入れる。

### 2.3 環境足場

主だけでなく、岩棚・岩柱・倒木・崖・浅瀬などを途中の安全地帯や移動点として利用する。

- Stamina回復地点として既存仕組みを再利用する。
- 主と地形を交互に移動することで、巨大生物上だけの一本道感を減らす。
- 淵纏いのSnake → Rock切替を基準にする。

### 2.4 音・振動による予告

視覚マーカーだけに依存せず、主の動きを音と振動で予告する。

例:
- 足音の間隔が変わる。
- 鈴・札が鳴る。
- 禍根へ近づくと低い脈動音が強くなる。
- Shake直前に体鳴り・地響きを入れる。

初期は既存HUD予告を残し、SE実装後に視覚マーカーを減らす。

## 3. 主ごとの適用方針

### 石走り

コア: **突進誘導 + 環境破壊 + 背中登攀**

現行の第一主戦では、最小の石走り専用体勢値（初期値3）を使う。攻略順は `突進を観察 → 横回避 → Recover → 脚・角周辺の禍の隆起を斬る → 体勢を崩す → 膝をつく → 5秒以内に前脚または角から取り付く → 11地点Routeを登る → 3禍根だけを祓う → 鎮静` とする。通常時の斬撃は硬質部位に弾かれ、Recoverごとの有効斬撃だけが体勢値を1減らす。体勢値はHealthではなく、0は登攀開始機会を作るだけでCalmやCompletedへ接続しない。

取り付かなければ通常状態へ戻して体勢値を3へ戻す。取り付き成功後はMount Windowを無効化し、既存Grab Motion Warp、11地点Route、分岐、休息、Shake、Cling、Stamina、落下をそのまま使う。落下後は地上から同じ体勢崩しを再実行する。勝利条件は登録された3つの `AKakonActor` の全浄化のみで、`AKakonActor::Purify → UNushiProgressComponent::OnAllPurified → UNushiStateComponent::CalmNushi → ANushiEncounterManager::Completed → Victory` を唯一の通常攻略経路とする。

- 突進を岩壁・石柱などへ誘導し、Grab開始点または分岐を作る。
- 境断ちで禍の強い方向を探す。
- 左腕でShake前兆や禍の流れを短時間読む。
- 札は必要なら揺れを一度だけ抑える用途に限定する。

既存の11地点Route、3禍根、Grab/Stamina/Nushi進行を可能な限り保持する。

### 淵纏い

コア: **噛みつき誘導 + 岩と蛇の往復 + 巻き付き変形**

- 現行のBite → Rock → Snagged → Grabを正式な習性利用ギミックとして扱う。
- Coilingで身体ルートが変形する構造を身体変形ルートの代表例にする。
- 岩棚・岩柱はStamina回復と経路選択の基準。
- 将来的に境断ち/左腕で水面下の禍の方向や次に浮上する位置を読む余地を残す。

### 峰抱き

コア: **動く身体 + 崖登り + 姿勢変化 + Cling**

- 現行のBodyRoot姿勢変化と相対Transform追従を中核にする。
- 腕を崖へ掛ける瞬間などを「一時的な橋・足場」として利用できる構造へ発展させる。
- 禍根2/3以降では、単にClingを繰り返すのではなく、身体変形でルートが切り替わる判断を1つ以上入れる。
- 落下Recoveryは既存淵纏いの考え方を参考にする。

### 禍津根

コア: **3体で学んだギミックの統合**

- 新しい大規模システムを追加せず、習性/環境利用、境断ち、左腕、Grab/Cling/Staminaを組み合わせる。
- 破壊ではなく、複数の禍の流れを鎮めて核へ到達する。
- 最終局面でも「敵を殺す」より「自然現象として発生した禍を鎮める」テーマを優先する。

## 4. 実装優先順位

新規ギミックは以下の順に入れる。

1. **主の攻撃・習性を利用する環境ギミック**
   - 淵纏いに既存実装があり、最小リスク。
   - 石走り・峰抱きへ1つずつ展開する。
2. **境断ちの探知 / 看破**
   - 現在のデバッグ的な禍根・ルート誘導表示を段階的にゲーム内表現へ置換する。
3. **穢れた左腕の感知 + 1種類のRisk**
   - 最初から複数デバフを実装しない。
4. **札・注連縄の一時封印**
   - 主ごとの攻略差別化が必要な箇所だけ追加する。
5. **音・振動・自然現象による補助表現**
   - VFX/SE/最終ポリッシュ段階で統合する。

## 5. 現在の5STEP計画への統合

### STEP 1 — 峰抱きを3/3まで完成

- 現行1/3 Sliceを壊さず、禍根2・3、Calm、Completed、Victory、Retryまで実装。
- 最低1つ、身体変形によるルート判断を追加。
- 落下Recoveryを追加。
- 境断ち/左腕/札はこの段階では本実装しない。後付けできるHookだけ許容。

### STEP 2 — 禍津根をPrimitiveで完成

- 3体で成立したギミックを再利用。
- 新しい大規模基盤は作らない。

### STEP 3 — 全編接続 + ゲーム内ギミック導入

- 境断ちの探知/看破を導入。
- 左腕感知を最小仕様で導入。
- 必要な主だけ札封印を導入。
- 常時デバッグマーカーを段階的に削減。

### STEP 4 — 本番3D / Animation / VFX / Audio

- 刀身反応、左腕の禍表現、札、環境破壊、主の予告を視覚・音響で表現。

### STEP 5 — 人間のプレイテスト / 調整 / Package

- ギミックが初見で理解できるかを確認。
- 誘導が強すぎて答えを直接表示していないか確認。
- 逆にノーヒントで詰まらないか確認。
- Keyboard / 物理Gamepad / Packageで通し確認。

## 6. スコープ外

現時点では以下を本仕様の必須要件にしない。

- クラフト、装備強化、札の在庫管理
- 複雑な属性相性
- 大規模なスキルツリー
- 物理ベースの自由登攀全面置換
- 主ごとに完全別の操作体系
- 天候シミュレーションを攻略必須にすること
- 禍ゲージを複数段階の状態異常システムへ発展させること

個人開発として、既存共通基盤の再利用と主ごとの少数の固有ギミックを優先する。

## 7. 設計上の最終目標

『禍祓い』の主戦は、次の体験を目標とする。

`観察する → 主の習性を利用する → 道を作る/見抜く → 巨体へ取り付く → 動く身体を登る → 禍根を見つける → 禍だけを祓う → 主を鎮める`

「巨大な敵のHPを削って倒す」のではなく、**巨大な主の行動・身体・地形を読み解き、禍だけを切り離す**ことを本作のゲームプレイ上の独自性とする。

## STEP 3A implementation status (2026-09-14)

**Implemented in source:** shared registered-target `UPlayerSenseComponent`; Boundary Sense direction/strength/distance bands; phase-filtered Kakon selection; sense-gated route/Kakon debug primitives for the connected encounters; separate corruption warning categories; one 50% stamina-recovery risk with a two-second tail in the three `UStaminaComponent` encounters; Q/LT and F/LB hold mappings; HUD status; retry reset; debug telemetry; Gherkin, source-contract and UE Automation coverage. See [Player Sense Gameplay](PlayerSenseGameplay.md).

**Not implemented:** production sword/arm VFX and audio, full campaign connection, talismans/shimenawa, continuous authored warning lead times, a new combat system, or changes to the existing Kakon purification lifecycle. Windows UE build/runtime/regression validation and the legacy Ishibashiri scalar-stamina risk hook remain outstanding.
