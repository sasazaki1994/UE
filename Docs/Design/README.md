## 決定事項と提案を区別する

- ユーザー指定: 仮面は封印具ではない。顔にも穢れがある。序盤は影響が小さく、進行に伴い強く見せる。制作差分は約2パターンに抑える。
- 本版の制作基準案: 前半は「通常」、淵纏い鎮静後の幕間から「進行」。同一モデル・リグ・衣装・アニメーションを共用し、マテリアル差分だけにする。
- 物語初稿: 一族の来歴、境界石での受傷、島への共鳴、仮面を着け直す結末は、最新の会話案を収録したもの。ユーザーが個別に確定した設定と混同しない。
- 旧案との要確認点: 以前の「自分の穢れを祓う旅」に対し、最新稿は「主と島を鎮める役目」を主軸にしている。自己救済を旅立ちの動機にも残すかは、台詞・プロローグの本実装前に確認する。

## 工数上の制約

- 白面の外見は2種類だけ。主戦ごとの追加段階、エンディング専用の第三形態は作らない。
- 素顔モデル、眼球の独立マテリアル、仮面の着脱機構の有無は要確認。既存資産にない場合、マテリアルだけでは作れない。
- 膝をつく、仮面をずらす、水面反射、注連縄を結ぶ、といった専用アニメーションは必須にしない。幕間・結末は既存カード画面＋静止画で成立させる。
- 島の地図は場所の関係を定義する概念図。オープンワールド、NPC、拠点往復、自由探索を新規必須機能にしない。
- 通常HUDを削るのは視覚・音・任意の補助表示が実機で読めることを確認した後。現行の誘導を今すぐ削除しない。
- UEビルド、入力攻略、見た目、音、操作感は静的検査のPASSで代替しない。

## 現在のソースとの関係

石走りの体勢崩し、4戦の共通浄化進行、Campaignの章順、Senseに加え、物語カードと章から導出する `Early` / `Advanced` 管理APIはソースにある。マテリアルへの2パターン接続、本番島マップ、本稿の音響・映像演出は未実装として扱う。淵纏い・峰抱き・禍津根のPlayerが簡易形状である場合、既存の白面モデルへ接続する作業も次工程とする。
